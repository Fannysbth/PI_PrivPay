### M1-02 `authenticate`: dua token (ADR-0007)

- Ditambah: `authenticate(headers, {clock, issuer, service, resolveKey, acceptCustomerToken?})` di `@privpay/common`. `requestingService` hanya dari `azp` token `Authorization` lewat allowlist (api-gateway, transaction, fraud, notification, reconciliation, admin-console → ADMIN_CONSOLE, bank-simulator → BANK; nasabah → CUSTOMER hanya bila gateway memintanya); klaim lain, header lain, dan body tidak pernah memengaruhinya (D-16, TK-07). Token aktor: harus orang admin-console dengan tepat satu peran; token layanan, nasabah, atau bank sebagai aktor ditolak; token orang di `Authorization` menolak `X-Actor-Token`; `aud` kedua token harus memuat layanan penerima (K-03). Umur token dibatasi 300 detik di sisi penerima (`maxLifetimeSeconds`). Kegagalan: `UNAUTHENTICATED` atau `FORBIDDEN_ROLE` dengan kategori pendek sebagai `cause`, tidak pernah isi token.
- Hardening `verifyJwt`: penulisan base64url non-kanonik ditolak (N-15).
- Aturan lint (kriteria wajib hasil Fase 2): `no-restricted-syntax` melarang `===`, `!==`, `==` dan `Buffer.equals` pada operan bernama rahasia (N-16). Terbukti pada kode nyata: perbandingan `client_secret ===` di dev-idp dilaporkan, dikembalikan; seluruh repo lulus tanpa positif palsu.
- Tes: 33 `authenticate` (diulang 15 kali tanpa kegagalan setelah memperbaiki satu tes yang kadang lolos), 1 `jwt` baru, 2 aturan lint. Mutasi (masing-masing membuat tes gagal): identitas ganda diizinkan, bank/nasabah boleh meneruskan orang, azp aktor tidak diperiksa, nasabah diterima layanan lain, service account boleh membawa `roles`, `aud` aktor tidak diperiksa.
- Dependensi: tidak ada. Keputusan sementara N-13..N-16 di `docs/OPEN_QUESTIONS.md` bagian G.

- Review M1-02 (perbaikan): klasifikasi pemanggil dipakai bersama oleh token `Authorization` dan token aktor (satu `principalOf`), sehingga `roles`/`customer_id` pada jenis yang salah 401 di kedua jalur dan token aktor sahih yang bukan orang admin-console 403 `not_a_person`; penerima memeriksa `ROLE_SERVICES` (K-03) sendiri, tidak hanya `aud` dari penerbit (matriks 3 peran × 6 layanan, untuk token `Authorization` dan aktor); skema `Bearer` tidak peka huruf besar-kecil dan `parseBearer` dipakai juga oleh dev-idp; kategori kegagalan bertipe `AuthFailure`; `ROLE_AUDIENCES` dev-idp diambil dari `ROLE_SERVICES` (satu sumber); tes negatif token aktor dilengkapi (penanda tangan lain, `alg=none`, HS256, `iss` salah, peran 0/2/tak dikenal/`bank`, `customer_id`) dengan kode tepat, bukan "salah satu"; aturan lint ditambah argumen `.equals`, `Buffer.compare`, kunci string `request['client_secret']`, dan `void 0` (8 pelanggaran di fixture). Tidak diubah: pemeriksaan `typ` (penerbit tunggal, tanpa jenis token lain); header ganda `authorization` di Node (hanya yang pertama sampai ke aplikasi; cabang larik untuk adapter lain).
### M1-01 `dev-idp`: penerbit JWT tiruan khusus dev

- Ditambah: `tools/dev-idp` (`@privpay/dev-idp`). Inti `IdentityProvider` tanpa framework: `client_credentials` untuk lima service account (rahasia dari `secrets/<klien>_client_secret`, dibandingkan lewat digest SHA-256 dan `safeEqual`), `dev_login` untuk pengguna seed (tanpa kata sandi), JWKS dari kunci RS256 yang dibuat saat start dan tidak pernah ditulis, token ≤ 300 detik dengan `iss=privpay-dev-idp`, `aud` per klien (service) atau per peran (manusia, spec 7 butir 6), `roles` tepat satu untuk manusia, `customer_id` hanya untuk `customer-app`. API admin `POST /admin/users` (hanya `{username}`) dan `DELETE /admin/users/{customer_id}` hanya untuk `api-gateway` (token untuk audience `dev-idp`): tanpa/rusak/kedaluwarsa 401, klien lain atau manusia atau audience lain 403 (AZ-38, AZ-39).
- Seed fiktif `tools/dev-idp/users.dev.json`: 3 nasabah (`CUST-000101..103`), 2 admin, 2 auditor, 1 fraud analyst, 1 bank; setiap manusia satu peran. Menolak start bila `NODE_ENV=production`, `DEV_IDP_ENABLED` bukan `true`, `BIND_HOST` bukan loopback, rahasia klien hilang/pendek/kembar, atau `ACCESS_TOKEN_TTL_SECONDS` di luar 1..300. `make-secrets` membuat rahasia dev (tidak menimpa, hanya nama berkas dicetak).
- Ditambah di `@privpay/common`: `safeEqual` (`timingSafeEqual`; panjang beda = false; bukan string/Buffer = false), `signJwt`/`verifyJwt` (RS256 saja; `none`, HS256 dengan kunci publik, algoritma lain, `crit`, `kid` tak dikenal, tanda tangan, `iss`, `aud`, `exp`, `nbf`/`iat` diperiksa; tanpa toleransi; jam disuntik), dan `ServiceDefinition.modules` boleh berupa fungsi `({env, clock}) => modul` yang dipanggil setelah konfigurasi platform sah (`ConfigError` dari layanan ikut jalur gagal-cepat).
- Dependensi: tidak ada paket baru di lockfile. `@nestjs/common`, `reflect-metadata`, `zod` (prod) dan `supertest`, `@types/supertest` (dev) sudah dipakai `@privpay/common`; kini juga dideklarasikan di `@privpay/dev-idp` (MIT/Apache-2.0). `pnpm audit --prod --audit-level high`: tidak ada kerentanan.
- Tes: 32 inti (token, JWKS, peran, audience, TTL, `safeEqual` dengan mata-mata, admin N1..N4, penomoran, penghapusan), 14 seed, 39 HTTP/konfigurasi, 2 skrip rahasia, 14 `jwt`, 6 `safeEqual`, 4 asap (proses hasil build: JWKS, dev_login, SIGTERM di Linux, tiga penolakan start), 3 tes struktur. Mutasi (masing-masing membuat tes gagal): `safeEqual` diganti `equals`, tanpa pemeriksaan panjang, tanpa pemeriksaan `alg`/`aud`/`exp`, tanpa pemeriksaan `azp` admin, tanpa pengikatan peran-klien, tanpa daftar audience, tanpa batas TTL, body diurai sebelum pemanggil diperiksa, `strictObject` jadi `object`, `production` diizinkan, TTL maksimum 3600.
- Keputusan sementara N-08..N-12 (`docs/OPEN_QUESTIONS.md` bagian G): hanya `username` pada API admin; nomor `CUST` berlanjut setelah seed; daftar `aud` per klien diturunkan dari alur panggilan; 403 vs 401; `safeEqual` dan format token dikerjakan di M1-01. Utang DK-04 (pemetaan klaim ke Keycloak) tercatat di README dev-idp.

- Review M1-01 (perbaikan): `NODE_ENV` tidak lagi peka huruf besar-kecil dan spasi (`Production` ditolak); `verifyJwt` punya opsi `maxLifetimeSeconds` (penerima: 300) sehingga token dengan `exp` jauh di depan ditolak walau tanda tangannya sah, dan tanda tangan diperiksa sebelum payload diurai; kategori kegagalan JWT menjadi tipe `JwtFailure` (dev-idp membandingkannya, bukan string bebas); `isServiceClient` menggantikan cast; `notification` boleh meminta `aud=sms-simulator` (AZ-41, temuan review Spec); README dev-idp mencatat bahwa `dev_login` tanpa kata sandi (tiap proses lokal dapat meminta token) dan mode berkas `0o600` tidak berlaku di Windows; nama satu tes diperkecil klaimnya (hanya membuktikan `timingSafeEqual` dipanggil). Tidak diubah: daftar `CLIENTS` di `make-secrets.mjs` (skrip `.mjs` tidak dapat mengimpor TypeScript; sebuah tes membandingkannya dengan registri); `BIND_HOST` tetap menerima `::1` selain `127.0.0.1` (keduanya loopback, aturan bersama semua layanan).

- Ditambah: `@privpay/common` modul `migrate`: `readMigrations(root, mode)` (berkas `NNNN_nama.sql` di `common/` lalu folder mode, satu urutan 1..n tanpa celah atau duplikat, checksum SHA-256 dengan akhir baris dinormalkan agar checkout dengan autocrlf tidak dianggap berubah) dan `migrate(pool, {root, mode})`: menolak peran yang bukan pemilik database sebelum mengubah apa pun, kunci advisory per database (`MIGRATION_LOCK_KEY`), tabel `schema_migrations(version, name, checksum, applied_at)`, satu transaksi per migrasi, riwayat diverifikasi lebih dulu (berkas terapan berubah, hilang, atau berganti nama gagal, termasuk pindah mode pada database yang sama). `MigrationError` hanya memuat nama berkas, tidak pernah isi SQL; error basis data asli ada di `cause`.
- Tanpa rollback otomatis dan tanpa dependensi baru. 18 tes unit dan 15 tes integrasi (peran asli; checksum, urutan, peran salah, transaksi batal, idempoten, kunci).
- Mutasi: cek pemilik dimatikan → 1 tes gagal; cek checksum dimatikan → 1 tes gagal; kunci advisory dimatikan → 2 tes gagal (tes pertama lolos, jadi diganti tes yang menahan kunci dari koneksi lain dan menunggu lewat `pg_locks`, tanpa sleep).
- Review M0-04: `readMigrations` menolak symlink/junction (lstat) dan mengubah error baca (ENOTDIR, EACCES) menjadi `MigrationError` `unreadable`; koneksi yang tidak bisa rollback ditandai kelas `UnusableConnection`, bukan lewat bentuk `cause`; dokumentasi bahwa `cause` tidak boleh dicatat ke log; tes: polling kunci dibatasi dan hanya menghitung kunci di database tes, waktu diperiksa dengan `now()` basis data, helper fixture bersama, asersi nama berkas pada pesan error.
- Keputusan lain yang diambil runner (spec tidak menentukan): `root` diberikan pemanggil (pemetaan layanan ke `services/<svc>/migrations` ada di pemanggil, M0-06 dan tiket skema); "pemilik skema" dibaca sebagai pemilik database (satu database satu layanan, jadi sama dalam praktik); aturan "mode baseline tidak menjalankan migrasi Privacy Service" (data-dan-migrasi.md) adalah tugas pemanggil, bukan runner; checksum atas isi dengan akhir baris dinormalkan.
- Keputusan: nomor berkas berlanjut dari `common` ke folder mode (satu urutan), sehingga berkas `common` baru tidak bisa disisipkan setelah berkas mode ada; folder mode yang tidak ada dianggap kosong, folder akar yang tidak ada adalah error.

### M0-05 bootstrap DB multi-layanan dan harness tes

- Diubah: `scripts/db/bootstrap.sql` dan `bootstrap.ps1` kini membuat satu database dan pasangan peran pemilik/runtime untuk tiap layanan (privacy, transaction, fraud, notification, reconciliation; privacy tetap `privpay_app` dan `privpay_auditor`), hanya peran milik layanan yang boleh terhubung ke databasenya, dan keanggotaan sementara admin pada semua peran pemilik dicabut di akhir. `ALTER ROLE` hanya menyinkronkan kata sandi (admin non-superuser tidak boleh menyatakan ulang atribut SUPERUSER). - Ditambah: `@privpay/common` modul `db` (`SERVICE_DBS`, `pgConfigSchema` untuk `PG_HOST`/`PG_PORT`/`PG_SECRETS_DIR`, `createPool`, `readRolePassword`, `withTransaction`; semua nama harus berawalan `privpay_`) dan `@privpay/common/testing` (`createTestDb`, `createAdminPool`, `testDatabaseName`): membuat ulang `privpay_<layanan>_test_<akhiran>` oleh `privpay_test_admin`, menerapkan skema sebagai pemilik, dan mengembalikan pool untuk peran runtime asli.
- `pnpm test:integration` (Jest terpisah, satu worker, pengaturan dari `.env.test` atau env; tanpa kata sandi). 26 tes unit dan 23 tes integrasi baru.
- Bukti: bootstrap dan 23 tes integrasi dijalankan terhadap klaster PostgreSQL 18 sementara dengan admin non-superuser (bukan server Fanny, bukan `.env` Fanny), dua kali berturut-turut (idempoten). Mutasi `GRANT CONNECT ... TO PUBLIC` membuat dua tes isolasi gagal. **Belum dijalankan di server Fanny**: Fanny perlu menjalankan ulang `scripts/db/bootstrap.ps1` lalu `pnpm test:integration`.
- Dependensi baru: `pg@8.23.1` (MIT) di `@privpay/common` (driver PostgreSQL, ADR-0002, sebelumnya hanya di prototipe) dan `@types/pg` (dev, MIT). `pnpm audit --prod --audit-level high`: tidak ada kerentanan.

- Review M0-05: `createTestDb` menutup semua pool bila gagal di langkah mana pun dan pool/klien admin punya handler `error`; tes baru memeriksa bahwa hanya `privpay_test_admin` yang punya `SET`/`INHERIT` pada peran pemilik (admin bootstrap tetap memegang opsi ADMIN bawaan PostgreSQL 16+, dijelaskan di `scripts/db/README.md`). Deviasi dari teks tiket, disengaja: nama database tes memakai akhiran (`privpay_<layanan>_test_<akhiran>`) agar berkas tes paralel tidak berbagi database (spec platform bagian 11), dan `schema` berupa SQL mentah yang dijalankan sebagai pemilik sampai runner migrasi (M0-04) menggantikannya. Idempotensi dua kali jalan diperiksa manual pada klaster sementara, belum otomatis.

- Syarat penerimaan M0-05 (Fanny): mutasi tes keanggotaan (memberi `SET`/`INHERIT` pada peran pemilik ke admin bootstrap) membuat tes gagal, dan lulus lagi setelah dicabut. Idempotensi bootstrap tidak dapat diuji otomatis secara lokal tanpa membaca kredensial admin, jadi dipindah ke CI (kriteria baru M0-07) dan diperiksa manual pada klaster sementara (dua kali jalan, hasil sama). ADR-0004, kriteria M0-05, dan spec data-dan-migrasi dikoreksi: opsi ADMIN pembuat peran tidak dapat dicabut. Bootstrap di server Fanny berhasil (admin superuser); `test:integration` di sana menunggu `.env.test` (salin dari `.env.test.example`).

### M0-03 `@privpay/common`: klien HTTP antar-layanan dan cache token

- Ditambah: `createHttpClient` (timeout `AbortSignal.timeout`, retry hanya untuk operasi idempoten pada kegagalan jaringan, timeout, 502/503/504 dengan backoff eksponensial dan jitter 0,5x..1,5x, 4xx dan 500 tidak diulang, redirect tidak diikuti, `X-Request-Id` diteruskan atau dibangkitkan, URL hanya dari konfigurasi dan path dibatasi pola, respons dibatasi 1 MiB), `createTokenCache` (cache sampai `exp` dikurangi 30 detik, satu fetch bersama untuk pemanggil paralel, kegagalan tidak di-cache dan tidak mengutip token), dan `Delay` (`RealDelay`, `FakeDelay`).
